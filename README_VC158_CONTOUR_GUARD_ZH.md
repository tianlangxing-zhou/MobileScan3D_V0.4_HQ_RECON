## 重叠风险与处理

本次没有收到问题扫描的深度/位姿记录或模型，因此以下是已确认的代码风险及防护，不是对这次实拍唯一根因的断言。

- 原代码即使 TSDF 拒绝了当前深度，累计场景 Surfel 仍会走 zEpoch 兜底继续写入。现统一累计点云与网格接受条件；单帧相机坐标目标调试层仍可显示。
- 原时序检查只覆盖距最后接受帧 1.5 秒以内。持续冲突一段时间后，会失去比较条件。现保留已接受参考，不再因等待时间到期自动解除一致性检查。
- 原时序状态跟随 live 标定是否暂时 usable，而实际融合使用冻结 epoch。现按实际冻结深度空间匹配历史，避免 live 标定短暂失效时绕过检查。
- 新增 FusionGuard：保留第一张接受的参考帧及最多三张空间分离的近期参考帧，以相对相机位姿重投影比较。参考只保存已通过全部融合条件、且像素权重大于零的数据；拒绝帧不推进参考。绕回已有区域时，仍可与早期表面比较。
- 相邻帧及参考帧的有效重叠区一致比例低于 60% 时，拒绝当前密集融合；时间戳重复/倒序的回调在修改标定和几何前直接拒绝。当前帧已经判定时序或参考冲突时，稀疏 stereo 写入也不能绕过该判定。
- 仅几何融合执行后标记网格为 dirty，减少纯拒绝帧触发的无效网格重建。

FusionGuard 使用每四像素的参考重投影，至少 `max(32, 图像像素数/256)` 个可比样本才做整帧拒绝；深度容差为 `max(12 mm, 当前深度的1.8%)`（坐标按现有 VINS 世界尺度）。最多四张参考图；256×256 时参考深度约 1 MiB。空间间隔约 0.1 世界单位或 15° 才加入参考，第一张始终保留。当前场景完全没有重叠时仍允许新区域进入，不能据此证明位姿准确。

## 色块轮廓算法

对与深度同曝光的 FrameSnap RGB 做以下处理：

1. 按现有 RGB/深度像素对应缩放，3×3 分离式均值降噪。
2. 在 RGB 三通道计算颜色差异梯度，兼顾亮度边界与灰度相近的不同色块。
3. 非极大值细化，梯度阈值 24/255；8 邻域连通筛选，去掉不足 5 像素的孤立响应。
4. 轮廓扩成一像素邻域的优先带，只保留有限、正深度及非零可信度的像素。
5. 场景与目标 TSDF/点云均先处理边界带，再处理其他区域。边界跳过稳定平面抽稀，避免 2 cm 共面预览压缩吞掉轮廓，保留原 1 cm 预览分辨率。
6. 点云显示预算不足时，最多优先分配约一半给符合 minHits 的轮廓点，其余覆盖普通表面；某一类不足时自动转用剩余额度。同一帧中后处理的普通像素不会擦掉同体素的边界标记。

**点的位置仍来自原深度和原位姿。** 不会把点强行吸到 RGB 边缘、不提升深度置信度、不对孔洞补造深度。色块边界用于加密和保留曲线轮廓；平面上的涂色线不会被当作空间折痕。当前实现不输出独立样条/矢量曲线，也不增加新的 UI 开关，默认启用。

颜色处理缓冲复用，时间复杂度 O(像素数)。超过 1024×1024 的深度图禁用这项颜色引导，保留原几何融合，限制额外内存与 CPU 开销。

## 诊断与边界

原生诊断文本新增 `Fusion guard`（参考数、检查数、拒绝数、重叠样本、一致比例、重复回调）以及 `Color contours`（轮廓像素、优先带像素）。

本次未完成 Android 全工程编译或真机扫描。附件不包含完整 Android 外部依赖；JNI 编排与设备行为仍需在原构建环境/手机验收。

这次实现的是一致性保护和颜色引导，不是全局位姿图优化、ICP 轨迹修正或离线重建。慢速累积位姿漂移、无重叠视角、运动物体和低于深度容差的重复薄层仍可能存在；参考冲突时会暂缓累计而不是自动把轨迹拉回。颜色纹理会增加边界保留量和部分帧融合成本。更改相机内参或坐标尺度应新开扫描，避免将不同空间混在旧模型中。
