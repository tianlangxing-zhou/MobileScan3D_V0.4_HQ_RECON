## 2.2 Renderer

仍然使用工程已经验证过的同一套相机几何：

```text
Pc = Rwcᵀ × (Pw - twc)
      ↓
Camera2 fx/fy/cx/cy
      ↓
cameraToView
      ↓
OpenGL NDC
```

没有引入第二个 AR Camera。

```text

        ↓ unavailable

```

因此纹理上传失败也不会让 V0.5 的网格 AR 一起消失。

## 2.3 为什么继续 GLES2

没有强制整个项目升级 GLES3/Vulkan。

V0.6.1 在上传时把 indexed mesh 一次性展开成：

```text
position3 + uv2
```

然后：

```text
glDrawArrays(GL_TRIANGLES)
```

默认 80k triangles：

```text
80,000 × 3 × 5 × 4 bytes
≈ 4.8 MB VBO
```

避免依赖：

```text
OES_element_index_uint
```

对老 GLES2 Android 驱动更稳。

---

## 2.4 UV Y 方向

V0.6 atlas 使用 glTF 约定的 UV。

Android `Bitmap -> GLUtils.texImage2D` 后，V0.6.1 **直接使用 baked UV**：

```glsl
vUv = aUv;
```

不会再额外做第二次 Y flip。

# 3. V0.7：为什么没有直接序列化 VINS Estimator

上游 VINS-Mono 有 pose graph reuse / relocalization 体系，但它依赖完整：

```text
pose_graph
BRIEF
vocabulary
keyframe database
ROS-side persistence/reuse pipeline
```

你当前 Android 工程主要集成的是：

```text
Estimator
FeatureTracker
IMU
FeatureManager
```

直接序列化这些运行时对象尤其是：

```text
MarginalizationInfo
preintegration pointers
sliding-window optimization state
```

会把扫描文件和：

```text
VINS version
window size
Ceres internal state
memory ownership
```

绑死。

所以 V0.7 保存的是**稳定的几何产品**：

```text
VINS world 3D point
+
ORB descriptor
```

而不是保存滑窗优化器内存。

# 4. Persistent VINS Map

新增：

```text
persistent_relocalizer.h
persistent_relocalizer.cpp
```

扫描过程中：

```text
VINS NON_LINEAR
        ↓
triangulated FeaturePerId
        ↓
anchor camera 3D
        ↓
saved VINS world XYZ
        ↓
current visual-frame pixel
        ↓
ORB descriptor at that exact VINS feature pixel
        ↓
persistent map
```

## 4.1 时间同步

VINS image processing 约 10 Hz，而 Camera2 通常更高。

V0.7 新增：

```text
g_lastEstimatorImageTimestampNs
```

只有：

```text
当前 gray timestamp
≈
实际进入 Estimator::processImage 的 timestamp
```

误差 <= 2 ms 时，才允许：

```text
current ORB descriptor
↔
current VINS triangulated 3D point
```

避免把 30 Hz 相机图像与 10 Hz VINS 状态错配。

---

## 4.2 地图关键帧

不会每帧保存。

触发条件任意一个满足：

```text
translation >= 12 cm

OR

rotation >= 10°

OR

distance from last map keyframe >= 2 sec
```

持久 map 上限：

```text
12,000 3D landmarks
```

每个 landmark：

```text
x y z : float32
ORB    : 32 bytes
```

一个典型 5,000 点地图大约只有：

```text
5000 × (12 + 32)
≈ 220 KB
```

另加很小文件头。

---

## 4.3 VINS 点继续优化

同一个 VINS feature 第一次进入 map 后不会无限重复增加 descriptor。

但如果它还在 VINS sliding window 中继续被优化：

```text
旧 ORB descriptor 保留
最新 VINS world XYZ 覆盖旧 XYZ
```

因此最终持久地图使用更成熟的 3D 坐标。

---

## 4.4 发布最低门槛

为了避免“文件保存成功但根本无法重定位”的假成功：

```text
map points >= 80
map keyframes >= 3
```

否则：

```text
nativeSavePersistentMap() = false
```

整个跨会话 AR package 不发布。

## 5.1 当前帧搜索

后台线程执行：

```text
current VINS-processed 640×480 gray
→ ORB <= 1600 features
→ Hamming BF match against persistent map
→ KNN ratio test
→ unique saved landmark
```

过滤：

```text
ratio < 0.75
Hamming <= 72
matches >= 20
```

---

## 5.2 PnP-RANSAC

```text
saved world XYZ
↔
current image UV
```

进入：

```text
solvePnPRansac
EPNP
200 iterations
4 px threshold
confidence 0.995
```

接受条件：

```text
inliers >= 16
inlier ratio >= 0.35
median reprojection <= 3 px
```

# 6. savedWorld ← liveVinsWorld

PnP 得到当前 camera 在 saved world 中的位置：

```text
T_saved_camera
```

当前 VINS 同时给：

```text
T_live_camera
```

所以：

```text
T_saved_live
=
T_saved_camera
× inverse(T_live_camera)
```

以后 live VINS pose：

```text
T_live_camera(t)
```

都转换成：

```text
T_saved_camera(t)
=
T_saved_live
× T_live_camera(t)
```

模型本身从扫描时起就在 saved world 中，所以不需要移动模型。

---

# 7. 防止错误跳转

第一次 PnP 成功**不会立即锁 AR**。

必须连续两次解满足：

```text
rotation difference <= 10°
translation difference <= 20 cm
```

才建立第一次 alignment。

建立后如果再次利用 saved map 修正 VINS drift：

```text
rotation delta <= 15°
translation delta <= 35 cm
inlier ratio >= 0.40
```

才接受，并用：

```text
10–25% smoothing
```

慢慢修正。

---

# 8. 未定位前绝不显示旧模型

这是 V0.7 一个重要安全行为。

加载 persistent map 后：

```text
mapLoaded = true
localized = false
```

此时：

```text
nativeGetRenderPose()
nativeGetRenderPoseAt()
```

返回 false。

也就是：

```text
旧模型不会先出现在新 session 原点
不会先画错，再瞬间跳到正确位置
```

只有视觉重定位真正完成以后，AR renderer 才得到 saved-world pose。

---

# 9. 重定位不会阻塞 Camera2/VINS

全帧：

```text
ORB detect
BF Hamming
PnP RANSAC
```

不能放 Camera thread。

V0.7 的 Camera2/VINS thread 只做：

```text
exact VINS processed frame
→ copy latest 640×480 gray
→ copy exact-time Rwc/twc
```

然后 `DepthInference` 后台线程调用：

```text
nativeTryPersistentRelocalization()
```

因此：

```text
Camera2/VINS thread
≠
relocalization compute thread
```

未定位时最多约：

```text
~2 attempts / sec
```

PersistentRelocalizer 内部还有 300 ms minimum period。

定位后：

```text
<= 1 attempt / sec
```

只做轻量 drift correction。

# 12. 实机流程

## 首次扫描

1. 打开 APP。
2. 等 VINS `NON_LINEAR`。
3. 开始扫描。
4. 缓慢绕物体/区域 220–360°。
5. 不要只盯物体本身；画面里保留有纹理、静态背景。
6. 停止扫描。
7. 导出 GLB / 等自动闭环。
8. 成功时会得到 HQ textured AR。
9. 后台完成后 Toast：

```text
跨会话 AR 已保存：<session>
```

如果提示：

```text
VINS 持久地图不足
```

说明：

```text
map points < 80
或
有效 map keyframes < 3
```

增加相机平移、侧面和背景纹理。

---

## 重开 APP

1. 回到原扫描环境。
2. 保持原主摄/相近焦段。
3. 点击：

```text
恢复AR
```

4. 屏幕会提示：

```text
地图已加载，请缓慢移动手机寻找原扫描区域
```

5. 缓慢左右平移 + 小角度旋转。
6. 未定位时模型保持隐藏。
7. 两次一致 PnP 后提示：

```text
AR 重定位成功
```

8. HQ texture model 才开始出现在保存的世界位置。

# 14. 这版“持久化 VINS map”的准确含义

V0.7 **不是**把 VINS sliding-window optimizer 整个 dump 到磁盘。

保存的是：

```text
VINS triangulated persistent world map
+
visual descriptors
```

然后新 VINS session 用视觉几何重新求：

```text
savedWorld ← liveVinsWorld
```

这是跨会话 AR 真正需要的东西。

优点：

```text
不依赖 MarginalizationInfo 内存布局
不依赖旧 preintegration pointer
不依赖某一次 Ceres problem
旧 map 更容易跨 App 版本兼容
文件很小
```

# 16. 当前局限

V0.7 已经是跨会话视觉重定位闭环，但不是最终 SLAM 产品。

### 1. BFMatcher 是线性搜索

最多 12k descriptors。

对单物体/房间局部扫描足够。

若未来保存几十/几百个位置，应进入 V0.7.1：

```text
BoW / DBoW3
或
hierarchical retrieval
```

先做候选 keyframe 检索，再 PnP。

### 2. 环境变化

如果：

```text
大面积换家具
光照极端变化
目标物体被搬走
全部是白墙
镜面/透明表面
```

ORB map 会弱。

### 3. 动态物体

当前 VINS map 来自全画面 feature。

尽量让地图包含：

```text
静态墙角
桌面纹理
书架
固定物体
```

而不是只有一个之后可能被移动的扫描物体。

### 4. 不做 cross-device 保证

当前首先保证：

```text
同一手机
同一主摄
相近环境
```

换设备需要进一步处理：

```text
更严格 camera calibration
descriptor domain shift
VINS extrinsic differences
```

### 5. 目前恢复最近一次扫描

V0.7 UI 提供：

```text
恢复AR
```

恢复最新完整 package。

`ScanPackageManager.list()` 已经支持枚举历史扫描。

下一版可以直接做：

```text
扫描历史列表
thumbnail
名称
删除
选择恢复
```
