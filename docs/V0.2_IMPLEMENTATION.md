# V0.2 HQ AI implementation notes

## Real now
- Camera2 capture, YUV_420_888
- IMU acquisition at high rate
- JNI transport to native C++
- Gaussian observation ingestion + spatial merge/stability bookkeeping
- TSDF bookkeeping
- Vulkan availability detection
- GPU shader entry points

## Intentionally placeholder
- Visual-inertial pose estimation (current VioEngine is an API scaffold)
- True depth estimation / multi-view stereo
- AI depth refinement and completion model weights
- Vulkan Gaussian projection, tile binning, sorting and rasterization
- Final mesh extraction

These are separated behind native modules so they can be replaced without changing the Android camera/IMU UI layer.

## Precision strategy
The engine is designed for repeated photography: keyframes should be retained only when sharpness, baseline, overlap and viewpoint novelty pass thresholds. A future confidence map should identify weak surface cells and request a next-best-view capture. Final local optimization should jointly refine poses, depth and Gaussian/TSDF geometry rather than simply duplicating the same frame.
