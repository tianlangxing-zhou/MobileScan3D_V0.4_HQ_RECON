## 1. HQ 纹理 AR（V0.6.1）

渲染链路保持工程原有相机几何，没有引入第二套 AR 相机模型：

```text
Pc = Rwcᵀ(Pw - twc) → Camera2 fx/fy/cx/cy → cameraToView → OpenGL NDC
```

纹理 Mesh 优先；HQ texture 不可用时自动退回原 vertex-color Mesh。
继续使用 GLES2，indexed mesh 展开为 position3 + uv2 后 `glDrawArrays`，
默认 80k triangles 约 4.8 MB VBO，不依赖 `OES_element_index_uint`。
UV 直接使用 V0.6 baked UV，不做二次 Y flip。

## 2. 持久视觉地图与重定位（V0.7）

保存的是稳定几何产品，而不是 VINS 滑窗优化器内存：

```text
saved VINS world XYZ + ORB descriptor
```

重定位：

```text
current ORB → Hamming match → solvePnPRansac → T_saved_camera
T_saved_live = T_saved_camera × inverse(T_live_camera)
所有 live VINS pose 转回 saved world
```

安全约束：

- map 发布门槛：`>= 80 landmarks` 且 `>= 3 map keyframes`。
- PnP 接受：`inliers >= 16`、`inlier ratio >= 0.35`、`median reprojection <= 3 px`。
- 首次定位需连续两次解一致（`<= 10°` / `<= 20 cm`）才锁定。
- 定位成功前 `nativeGetRenderPose*()` 返回 false，旧模型不会先出现在新会话原点。
- ORB detect / Hamming / PnP-RANSAC 在后台线程（约 2 次/秒），不占用 Camera2/VINS 线程。

扫描包（仅在 GLB + AR asset + 持久地图三者都成功时发布）：

```text
scan_packages/<sessionId>/{manifest.json, model.glb, ar_asset.msar, vins_map.vmap}
```

## 3. 本次落地时修复的编译问题

打补丁后首次 `assembleDebug` 失败，报错：

```text
app/src/main/cpp/ar_textured_asset.h:8:10: fatal error: 'uv_unwrap.h' file not found
```

原因：补丁头文件按“include 根目录即 payload 目录”的测试桩环境编写，
而真实工程中 `uv_unwrap.h` 位于 `app/src/main/cpp/v06/`，且 CMake 只把
`cpp/` 根目录加入 include 路径。

修复（1 行）：

```diff
- #include "uv_unwrap.h"
+ #include "v06/uv_unwrap.h"
```

与工程内既有写法（`native_engine.cpp` 使用 `#include "v06/uv_unwrap.h"`）保持一致。

## 5. 实机验收要点

1. 首次扫描：等 VINS `NON_LINEAR` → 开始扫描 → 缓慢绕行 220–360°，画面里保留静态有纹理背景 → 停止 → 导出。
2. 成功时应出现 HQ textured AR，并提示「跨会话 AR 已保存」。
3. 重开 APP，回到原环境，点击「恢复AR」→ 缓慢平移 + 小角度旋转 → 提示「AR 重定位成功」后模型才出现在保存位置。
4. HUD 第一轮重点看：`matches >= 20`、`inliers >= 16`、`ratio >= 0.35`、`median reprojection <= 3 px`。

## 6. 已知局限

- BFMatcher 为线性搜索（<= 12k descriptors），适合单物体/房间局部扫描；多地点需 BoW/DBoW3 检索（V0.7.1）。
- 光照剧变、大面积换家具、白墙、镜面/透明表面会削弱 ORB map。
- 当前只保证同一手机、同一主摄、相近环境的跨会话重定位。
- UI 目前只提供「恢复最近一次扫描包」。
