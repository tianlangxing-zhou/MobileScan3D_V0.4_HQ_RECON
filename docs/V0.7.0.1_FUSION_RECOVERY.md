# MobileScan3D V0.7.0.1 — Fusion Recovery Hotfix

## 问题现象

一次实机扫描（1775 个 tracking frame）导出得到空模型：

```text
VINS reject count = 1692        reject rate ≈ 95.3%
VINS lost latch = true
invalid feature depth resets = 672

TargetMask valid = 1            Target mask area = 70854
但：
TargetModel tsdfVoxels = 0      TargetModel fuseFrames = 0
TSDF voxels = 0                 blocks = 0
Mesh = 0 triangles
PLY vertex = 0                  fileBytes = 160
```

同时 VINS estimator 本身是正常工作的（`NON_LINEAR initialized`、`trackedFeatures = 141`、
`gravity = 9.800`），所以不是 VINS 没启动。

## 根因：一个没有恢复入口的状态机

旧代码：

```cpp
if (sane && !vinsLostAfterInit) {
    // accept pose
} else {
    ...
    vinsLostAfterInit = true;
}
```

一旦某一帧出现 transient bad / non-finite pose，`vinsLostAfterInit` 被置为 `true`；
而后续的接受条件又要求 `!vinsLostAfterInit`，因此这个状态**没有任何恢复入口**。
一次瞬时异常即可永久锁死整个扫描会话。

它引发了完整连锁故障：

```text
一次 VINS transient bad pose
            ↓
vinsLostAfterInit = true（永久）
            ↓
nativeGetRenderPose() 永远返回 false
            ├──────────────────────┐
            ↓                      ↓
FrameSnap 停止写入            HQ displacement = 999
            ↓                      ↓
Depth 找不到带 pose 的快照      stableFrames = 0
            ↓                      ↓
fuseTargetDepth 从未执行        HQ scheduler 全部拒绝
            ↓                      ↓
TSDF fuseFrames = 0            HQ capture = 0
            ↓                      ↓
Mesh = 0 triangles             Texture views = 0
            ↓
PLY vertex = 0
```

HQ scheduler 的 `1239 (reject3A) + 535 (rejectMotion) = 1774` 正好等于候选总数，
即每一次机会都被挡掉，与 VINS 锁死完全一致。

## 关于深度缩放：`applied=1.000` 是正确行为

日志里 `rawMedian ≈ 4.215`、`VINS ROI median ≈ 0.179`，
DepthCalib 的 inverse 模型 `z = 1 / (scale * d + shift)` 代入
`scale = -1.470, shift = 11.922`：

```text
z = 1 / (-1.470 × 4.215 + 11.922) ≈ 0.175     ← 与 VINS 的 0.179 已经很接近
```

即本次全局 DepthCalibrator 已经对上尺度。源码在 global calibrator 可用时故意返回 `1.f`
以禁用第二次 target scale，目的是避免「全局 calibration × target scale」重复缩放。
因此 **不要去强行乘 0.05**，`applied=1.000` 不是问题所在。

## 修复内容

只改一个文件：`app/src/main/cpp/native_engine.cpp`

1. `vinsLostAfterInit` 由永久 latch 改为**当前 loss 状态**，后续 sane pose 可自动恢复，
   并统计 `VINS recoveries`。
2. 保留 `>0.5` world-unit jump 与 non-finite 拒绝，**不是无脑放宽 VINS**。
3. VINS 恢复后重新允许 `storeSnap()`。
4. `nativeGetRenderPose()` 不再被历史 latch 永久卡死。
5. Depth → Pose 从「第一个 `<50ms`」改为「**最近的 snapshot，最大 80ms**」
   （`kDepthSnapMaxDiffNs = 80'000'000LL`）。
6. current-frame 绿色 Depth Debug 从 VINS pose 匹配分支里移出来 ——
   它本来就是 camera-space，不应因为 VINS 掉一帧而消失。
7. 新增诊断字段：

```text
VINS recoveries
rejectStreak

DepthPoseSnap:
matches
misses
lastDiffMs
maxDiffMs
```
