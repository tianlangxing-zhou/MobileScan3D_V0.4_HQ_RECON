## 覆盖方法

此 ZIP 是 **VC160 → VC161 增量包**。解压到已有工程根目录，即包含 `app/`、`gradlew` 的目录，覆盖同名文件。ZIP 根目录直接是 `app/`、`tools/` 和说明文件，没有额外 `MobileScan3D/` 层。

保留原有 `local.properties`、Ceres、OpenCV、深度模型及 NanoTrack 模型。先备份本地未提交改动。
本轮修改了 `nativeRetainDepthFrame` 的 JNI 返回类型：Kotlin 与原生库必须一起重新编译，不能混用旧 `.so`。
本地执行 `./gradlew :app:clean :app:assembleDebug`，或在 Android Studio 完整重建并安装。

## 审核确认并修复的问题

| 问题 | 原因与修改 |
|---|---|
| 有效深度在推理完成前被丢弃 | 任意后续帧暂时拿不到位姿，就清空快照队列和已钉住的源帧。现在短暂无位姿保留过去的有效快照；真正世界重置、非有限位姿或大幅跳变仍使快照失效。 |
| 在不能融合的帧上浪费推理 | `nativeRetainDepthFrame` 原来无返回值，失败仍推理。现在返回 Boolean，无源位姿立即释放 worker，下一相机帧重试，不消耗一次完整模型推理。 |
| 旋转／缩放时跟踪框漂移 | 原先把仿射矩阵平移项直接加到中心，漏掉旋转／缩放。现在使用完整仿射中心变换、尺度更新，并先检查 RANSAC 内点数及比例。 |
| NanoTrack 与 KLT 时间不一致 | 原先跟踪后才更新彩色图，且每五帧一次。现在跟踪前提供同一曝光的 320 像素彩色缩略图，拒绝旧时间戳彩色输入并复用缓冲。 |
| 目标离开后再回来不搜索 | 原先 LOST 直接返回。现在 REACQUIRING、LOST 均保留不可变 ORB 身份，最多 5Hz 全画面搜索，直到成功、用户换目标、取消锁定或重置。 |
| 找回后状态看似正常但马上再次丢失 | 采纳候选框曾允许无有效特征点，并漏记成功帧时间戳。现在至少 15 个 KLT 点才提交状态，同时更新源时间戳、存在性和失败计数。 |
| Nano 校正后的框晚一帧发布 | 现在校正中心／尺寸后重新发布归一化框，供当前帧快照及 UI 使用。 |
| 异常相机输入存在越界风险 | JNI 新增尺寸、步长、时间戳和 Y/U/V 数组长度校验，复制异常立即返回；相机回调串行保护共享暂存区。Kotlin 预处理也拒绝截断平面。 |

以上是代码路径确认的问题，不等同于已通过你的手机日志确认每一项都是当前故障的触发因素。

## 深度与效率改动

- TFLite 输入／输出使用复用的 native-order 直接缓冲，输出一次批量复制，避免嵌套数组传输。固定模型输出表示不变；核对仓库模型为 FLOAT32 `[1,256,256,3] → [1,256,256,1]`。
- 增加有界 3×3 保边滤波，只在接近当前值的有效邻域内平滑，不填补空洞、不修改原始逆深度表示、不做随帧 min/max 尺度归一化。
- 稀疏标定改用局部中值，并拒绝深度边界或离群像素，减少单像素采样污染。已有 MAD／Huber 标定、冻结尺度、时序校验及模型重叠防护继续生效。
- 灰度帧通过 OpenCV 引用计数共享，去掉同一帧的重复克隆；局部 Nano 找回改为每三帧一次，为全画面搜索保留计算预算。
- 全画面找回使用双向描述子匹配、距离比筛选、RANSAC 几何、内点空间覆盖、尺度和可见比例检查，再要求两次不同曝光的候选框一致。局部找回提高身份阈值；不能确认身份时保持丢失。

这些改动减少特定开销，但全画面搜索也增加了丢失状态下的计算。没有手机实测，不宣称总帧率、温度或实物测距准确率提升百分比。

## 实机验收与下一步

1. 启动扫描后，缓慢移动手机产生视差，等待 VINS 和深度尺度初始化。观察 `retain ok/noPose`、`DepthPoseSnap misses`、`fusedFrames/gatedFrames`，确认点云持续累积。
2. 对同一静止、有纹理物体进行近→中→远扫描；远距测试前调整扫描范围。检查模型表面连续、没有重复壳，保存反馈报告。
3. 将物体移出画面 2 秒、10 秒后从不同位置移回；分别验证正常光照、轻遮挡、相似背景。查看 `globalSearchReady/globalSearches/globalRecoveries/globalInliers`。两次搜索确认最短相隔 200ms，实际找回耗时受帧率和设备负载影响。
4. 缓慢转动或改变手机距离，检查跟踪框中心和大小；持续扫描 3–5 分钟，比较 `DepthInferencePerf`、`PerfStage`、热保护和丢帧情况。
5. 如果 `retain noPose` 一直增长而 `ok` 为零，优先检查 VINS 初始化、IMU/相机时间对齐与标定；如果 `epochSusp` 或时序拒绝持续增长，需依据日志处理尺度漂移，不能通过关闭安全门伪造连续点云。

限制：完全遮挡、纯色／反光／透明物体、重复纹理、转到从未见过的背面，都不能保证持续身份锁定。新搜索记住的是用户框选时的身份，尚未实现多视角目标库。物体重新找到也不等于 VINS 世界坐标已经恢复；世界重置时仍须新建扫描。当前仍固定定位主摄，近中远调配辅助镜头。

下一轮最有价值的输入：手机型号、Android 版本、VC161 一段近中远＋出画返回视频，以及对应反馈报告。据此决定是否优先做 VINS 时间对齐、多视角目标库，或深度推理后端加速。
