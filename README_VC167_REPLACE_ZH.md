## 如何替换

### 已有工程：使用 Overlay 覆盖包

1. 备份原工程，停止 Android Studio 中正在进行的构建。
2. 打开 ZIP，将其中的 `app/`、`tools/` 和说明/清单文件合并到工程根目录，即与 `settings.gradle.kts` 同级。选择替换同名文件。**不要删除原来的 app 目录**：覆盖包不包含未改动的资源和依赖。
3. 保留本机 `local.properties`、Ceres 构建目录、签名配置。
4. 可运行 `python tools/review_tests/verify_vc167_overlay.py` 校验覆盖后的文件。
5. Android Studio 同步 Gradle，执行 Clean / Rebuild；或执行 `./gradlew clean :app:assembleDebug`（Windows 使用 `gradlew.bat`）。
6. 安装新 APK。若设备上旧包的签名与本次构建不同，应使用原签名构建；卸载会清除应用私有扫描文件，请先导出需要的模型。

覆盖包基于上述仓库和本次附件；如果本地还有未提供的 UI/算法改动，应先对比合并，避免覆盖那些改动。

### 重新打开工程：使用 Full 完整包

解压 `MobileScan3D_VC167/`，用 Android Studio 打开该目录，复制原工程的本机 `local.properties` 后构建。构建要求沿用原工程：JDK 17、SDK 36、NDK 27.1.12297006、Ceres 2.2.0 Android arm64 预编译依赖。详细依赖配置见 `SETUP.md`。完整包仍需外部 Ceres，不是无需依赖的预编译 APK。

## 已修复的明确问题

| 优先级 | 问题及影响 | 本次处理 |
| --- | --- | --- |
| 高 | `DepthCalibrator::usable()` 会保留旧标定为有效；新拟合失败后，冻结状态机仍将旧参数视为连续稳定观测，可能过早冻结、让标定失效计数不生效 | 将本帧拟合是否成功接入 epoch 判据。未冻结时必须有新拟合；已冻结时允许当前独立稀疏点验证已有映射。保留已有几何，不把等待时间当证据 |
| 高 | 冷启动时只检查参考深度跨度，未检查输出分辨力；参考点有跨度但拟合斜率接近零时，仍可能接受平板状深度映射 | 首次拟合也检查输出逆深度跨度，使用配置中的冷启动放宽系数 |
| 高 | 线性模型将以“米”计的输出跨度与“1/米”门限比较；正确的近距离拟合可能第二次更新就被拒绝 | 两种模型统一计算逆深度跨度，新增近距离重复拟合回归 |
| 高 | 纹理烘焙和引擎创建存在未包裹的 C++ 异常路径；Kotlin `catch` 无法截获越过 JNI 的 C++ 异常 | JNI 入口捕获异常并返回失败；纹理失败可以进入已有顶点色 GLB 回退；创建失败给出提示 |
| 高 | 关闭/重新创建会话时，相机帧的 VINS 阶段在状态锁外运行，可与重置交错 | 相机回调、创建、销毁共用串行锁，固定先相机锁、后状态锁；销毁清除保留深度快照和有效位姿标志 |
| 高 | 长时间烘焙可晚于所属会话结束，返回时覆盖下一场的 AR 资产；执行器中断不能强制停止 JNI | native 发布前校验会话世代；ExportManager 在主要阶段及回调处校验世代，过期任务不再执行后续回退/发布 |
| 中 | `nativeGetGaussians` 先取得数组再检查空值，`maxPoints*6` 存在有符号溢出风险 | 先判空与范围，使用 `arrayLength/6` 校验容量 |
| 中 | 相机权限拒绝后仍能进入依赖未初始化对象的入口；空摄像头列表直接 `first()` | 增加权限/系统就绪检查、重新授权和设置入口、空设备提示、初始化幂等保护 |
| 中 | 退到后台后相机已关闭，扫描标志仍为真；返回后可能沿用跨越时间空洞的定位状态，同时 HQ 采集已结束 | 退后台时结束并导出已就绪扫描，恢复后保持停止状态；IMU 在后台注销，前台重新注册。初始化尚未完成的扫描不导出旧模型 |
| 中 | 过期 Camera2 配置失败回调仍尝试启动后备会话 | 重试前检查当前相机身份、前台状态及是否已放弃打开 |
| 中 | `ACTION_CANCEL` 仍落入点选分支；触摸距离混用固定像素和 dp | 取消操作不再触发选物/对焦；使用一致的密度换算阈值 |
| 功能 | “连续单帧/旧版多帧”菜单仅给 native 的 `mode` 赋值，该变量未被融合流程使用，描述与实际行为不符 | 改为真正接入 `nativeSetVoxelProfile` 的“物体精细/物体快速/房间”档位，持久化设置，下次扫描应用；显示体素设置并明确它不是测量精度 |
| 性能 | 烘焙诊断遍历网格和全部关键帧时持有状态锁，阻塞位姿读取 | 使用本次烘焙已经复制的关键帧快照完成诊断，移除该遍历期间的状态锁 |

## 手机界面改动

- 通过系统栏与屏幕缺口 Insets 设置安全区域，预览、触摸和 AR 图层使用同一布局区域。
- 标题、HUD、工具栏的位置基于实测控件高度，取消对固定顶部偏移的依赖。
- 右侧工具栏使用限高滚动容器，剩余高度由窗口、标题和底部按钮计算；小屏/分屏时仍可滚动访问工具。
- 主按钮文案缩短为“开始扫描/停止扫描”，三组底部操作保持至少 48dp 高度，消除默认按钮最小宽度导致的拥挤。
- 设置按钮预留空间，标题过长省略；长内容设置对话框可以滚动。
- 保留透明 GLSurfaceView 在 TextureView 上方的合成方式，避免替换图层顺序后相机预览被遮挡。

Android 安全区处理依据：

## 实际验证结果

**已完成：**

- 全部 23 个应用 Kotlin 文件使用 Kotlin 2.2.20、Android 36 API 类及相应 AndroidX/TFLite 编译依赖完成静态编译，JVM target 17，通过；仍存在原有 Android API 弃用警告。`BuildConfig` 使用与新版本对应的临时编译常量。
- 修改后的 `native_engine.cpp` 通过主机 C++20 语法检查。使用仓库 OpenCV/Eigen 头、OpenJDK JNI 头；Android log/Vulkan 只提供声明桩。**这不是 Android NDK 链接验证。**
- 12 个 C++ 主机回归套件：`run.py`、`run_geometry.py`、`run_scan_policy.py`、`run_optimization.py`、`run_continuity.py`、`run_robustness.py`、`run_round23.py`、`run_round4.py`、`run_fusion_refinement.py`、`run_contour_guard.py`、`run_vc161.py`（无 OpenCV 扩展）、`run_vc167.py`。已覆盖 GLB 结构/坐标、TSDF 网格、拟合、距离过滤、深度细化和本次新增标定问题；相关套件启用 ASan/UBSan 等检查，LeakSanitizer 因主机限制关闭。
- 5 个 Kotlin 回归套件：预览/触摸坐标、深度预处理、DEPTH16、自动补光、burst 回调。包含 144 组预览映射、180 组查看/摆放位姿及 3840 组 burst 回调排列。
- `git diff --check` 通过；交付 ZIP 校验和、覆盖清单、文件校验验证见 `VC167_MANIFEST.json`。

主机曾出现编译器临时汇编文件截断；使用 `g++ -pipe` 重跑相关套件后通过。这是环境处理，不改动应用编译优化参数。

**尚未验证：**

- 本环境没有完整 Android SDK/NDK/Ceres 构建链和连接手机，未生成 APK，未执行完整 `assembleDebug`/原生链接。
- 未进行真机 UI 截图或自动化点击验收；手机厂商 Camera2 多摄流组合、实际帧率、功耗、对焦及 AR 重定位仍需设备验证。
- 没有将“单目相对深度+VINS 估计”提升为保证精度的测量系统；冻结映射跨视角变化、近距离低纹理/反光物体仍可能影响重建。首次标定输出门更严格，极平坦场景可能需要更多有纵深的观测。
- 本次为重点路径审查和可验证修复，不代表已穷尽所有竞态或实现完整全局重建优化。硬件 DEPTH16 未与 RGB 完成时空对齐，仍维持原来的非默认状态。

## 建议真机验收顺序

1. 首次拒绝相机权限，再点击启用相机；随后授权并确认预览和扫描正常。
2. 320/360/393dp 宽度、系统字体放大、手势/三键导航、刘海屏：检查设置、底部按钮、右侧滚动工具可见可点。
3. 手机缓慢平移形成视差，再围绕有纹理物体采集；观察标定等待、模型生长及暂停提示。
4. 分别选择三个重建档位，开始新扫描，确认反馈中体素尺寸变化。
5. 扫描期间按 Home / 锁屏，再返回：原扫描应结束并保留导出结果，不应悄悄继续跨空洞融合。
6. 停扫导出普通/HQ GLB；纹理缺失时验证顶点色回退和“保存 GLB 到文件”。模型生成中退出并重新打开，检查旧结果不会覆盖新扫描。
7. 快速开始后立即停止/退后台，确认未就绪时不导出上次模型；触摸被系统取消时不应意外选框。
