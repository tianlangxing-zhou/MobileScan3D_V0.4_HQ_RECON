## 使用方法

### 模型查看

- 点击“查看模型”：单指拖动旋转；双指张开放大、合拢缩小。
- 按住约 300ms 后拖动：平移。
- 长按“退出查看”：恢复模型中心、默认方向和自动构图。
- 点击“退出查看”：返回相机。
- 缩放仅改变观察相机距离，不修改模型尺寸、导出单位或扫描几何。
- 两指变一指后，须全部抬手再开始旋转，避免指针索引变化导致视角跳动。
- 初始构图考虑屏幕宽高比；缩放距离保留包围球与近裁剪间隔，并限制最远距离。

### 摄像头调配

点击工具栏“镜头”，选择“自动 / 近距 / 中距 / 远距”。

**扫描时保持定位主摄和其 ImageReader 不变，切换的是辅助物理摄像头。** 近距优先较大视场角，中距优先基线与重叠率较好的组合，远距优先较小视场角。保留“切换主摄”入口，但只能在停止扫描后使用，且会重建原生会话；先保存需要的扫描结果。

该方案不是消费相机式的主摄无缝变焦：辅助镜头变化不要求逻辑预览画面出现变焦效果，HUD 中的物理辅摄 ID 才是实际调配结果。跨主摄连续扫描仍需要额外的外参/位姿交接实现，未在本轮冒险加入。

| 当前档位 | 自动转近 | 自动转中 | 自动转远 |
|---|---|---|---|
| 近 | 保持至 0.55m | 大于 0.55m | 大于 1.75m 可直达 |
| 中 | 小于 0.35m | 0.35–1.75m 保持 | 大于 1.75m |
| 远 | 小于 0.35m 可直达 | 小于 1.25m | 其余保持 |

以上阈值是可调工程默认值，不是机型标定结果；在 `CameraRangePolicy.kt` 中集中设置。自动切换至少要求 3 个有效深度结果、候选持续 900ms、与上次成功切换间隔 3 秒。手动选择绕过自动稳定时间。失败后自动重试退避 10 秒。

距离来自当前帧**已标定的深度场**：优先可靠目标框，否则在未锁定目标时采样画面中心；最多 289 个不重复采样点，取中位数，检查覆盖率、离散程度和可用置信度。丢失目标、未完成标定、深度过期、NaN/Inf 或深度分层明显时保持当前档位。只接受与处理帧时间戳相同的原生结果，重复或超过 1.5 秒的深度不能触发切换。

HUD 的“（估计）”表示距离沿用 VINS 标定尺度，尚未经稳定双目物理尺度确认；不能当作精密测距。稳定双目尺度可用时才按 world-per-meter 换算。没有使用 `DepthScaleEstimator` 的 shadow 统计擅自修正点云。

### 硬件限制与失败处理

- Android 9+ 且厂商暴露逻辑多摄、至少两个可用物理摄像头，才可调配辅助镜头；否则保留原单摄路径。
- 候选须支持相同 YUV 输出尺寸，并通过已有的 4–80mm 工厂基线检查；有最小对焦距离时也据此过滤。
- 手机若只暴露一个可用辅助镜头，近/中/远可能共用它，HUD 会显示“共用”，不会伪造第三颗摄像头。
- 重建 Camera2 session 可能短暂停顿。新会话在 4 秒内失败/超时会尝试恢复上一辅助镜头；恢复也失败则停止扫描、保留模型并重开相机。
- 切换会清除旧双目几何/锚点，并重新标定；不会主动清空已有 TSDF。
- 若物理 CaptureResult 表明 HAL 改变了定位主摄的裁剪，停止融合、保留模型并恢复相机，避免以旧投影继续融合。厂商不返回物理元数据时，无法完整验证这种变化，必须实机验收。
- 默认扫描范围仍为原工程的 1m。要试远距重建，请先将扫描范围调到足够大；镜头调配不会偷偷改变重建距离限制。

## 修复和效率改进

1. 原查看器缺少双指缩放：接入 `ScaleGestureDetector`，处理长按与多指切换冲突。
2. 原重置视角保留已平移的中心：记录模型原始中心，重置时恢复。
3. 原竖屏按纵向视场构图可能裁掉宽模型：按较窄视场自动构图。
4. 空闲预览仍复制 Y/U/V 三个平面：空闲路径提前返回，仍正常关闭 Image 和更新状态。
5. 双目任务可无限排队：最多一个在途任务，忙时不再复制双目灰度图；统计缓冲复用。
6. 旧双目任务可能在关闭/换镜头/新扫描后提交：加入跨控制器原生操作锁、代次和会话检查。
7. 深度尺度统计虽然在 Kotlin 内限流，JNI 取统计仍逐帧执行：将 100ms 限流前移到 JNI 调用之前。
8. 热保护仅按成功推理计时，失败可能立即高频重试：单独记录每次推理结束时间用于热降载，成功时间仍用于延迟诊断。
9. Android 8/9 访问较新 Camera2 字段存在风险：对 API 28 的畸变字段及 API 29 的活动物理 ID 添加版本保护。
10. 手动切主摄时原生重建可能使用在途打开请求的旧内参：先在相机线程销毁旧会话，再用新相机配置创建；拒绝过期 CameraDevice/Session 回调。
11. 模型查看轨道/平移使用可复用数组，姿态变更统一投递 GL 线程；空/非法顶点包围盒不再进入查看。

没有宣称整机帧率或功耗已提升某个百分比：本次没有连接目标手机做前后对比。

## 替换与构建

1. 先备份原工程、`local.properties` 和重要扫描包。
2. 解压 ZIP，使用其中的 `MobileScan3D/` 作为工程根目录。可打开新目录，也可覆盖原目录的同名工程文件。
3. 保留本机 `local.properties` 中的 `sdk.dir`、`ceres.sourceDir`、`ceres.buildDir`；若设置了 `opencv.sdkDir`，仍须是兼容的 OpenCV 4.12。
4. Android Studio 执行 Gradle Sync，然后 `./gradlew :app:assembleDebug`（Windows 使用 `gradlew.bat`）。
5. 安装后确认界面版本为 `0.13.20-depth-range`，执行下列验收。

依赖版本保持 SDK 36、NDK 27.1.12297006、JDK 17、Ceres 2.2.0，详细配置见原有 `SETUP.md`。本次没有提供 APK，也没有在此环境完成 Android/NDK/Ceres 的最终链接。

## 实机验收顺序

1. 已有模型进入查看：两指连续放大/缩小到边界、抬起一指再抬起全部、重新旋转、长按平移、长按重置、退出与再次进入。
2. 静态目标在约 0.25 / 0.8 / 2m 各停留 5 秒，先建立 VINS 与深度标定；核对 HUD 距离来源、辅摄 ID 和物理结果，而不只看逻辑预览画面。
3. 在 0.35–0.55m、1.25–1.75m 边界来回缓慢移动，确认不会来回抖动；遮挡/低纹理/目标丢失时不应使用旧距离切换。
4. 手动近/中/远连续选择；拍 HQ burst 期间应延后切换，失败时应恢复原摄像头。
5. 切换期间锁屏/回前台、停止扫描、启动新扫描；确认没有旧会话覆盖、黑屏死循环或旧锚点混入。
6. 查看/导出切换前后同一模型，确认尺寸与原世界坐标未被缩放手势或辅助切换改写。
7. 保留每台机型的反馈报告和日志；记录实际 ID、crop、frame timestamp、切换耗时、depth 延迟与热状态。

## 下一步优化路线（按顺序）

**P0：先完成目标机型标定与切换验证。** 用同一物体与标尺在三档距离采集，确认 VINS 尺度误差、物理主摄与逻辑预览的 K/crop 一致性、可用辅摄组合、最小对焦距离和切换停顿。为每台设备保存能力表与合格组合，避免每次尝试厂商不支持的流组合。此阶段不要把“近/中/远”阈值当成通用镜头规格。

**P0：若需要主摄无缝切换，单独做定位交接。** 先实现主摄间同步图像与外参验证、各自内参/畸变/裁剪模型、旧相机到新相机的位姿变换、VIO 跟踪重初始化与世界尺度一致性门控，再允许连续 TSDF 融合。用同一模型切换前后的点云误差验收；仅设置 zoomRatio 或相机 ID 不足以保证正确。

**P1：用设备数据选择性能改动。** 对深度推理、图像拷贝、双目匹配、网格提取分别统计 p50/p95、在途数量、温度和耗电。再决定是否使用可复用 YUV buffer 池、NNAPI/GPU delegate、深度分辨率/频率自适应。复用图像内存必须与 depthBusy 的所有权绑定，不能在异步推理结束前覆盖输入。

**P1：质量优化。** 固定标定板/曲面物体数据集，对距离误差、边缘完整度、重复壳比例、重投影误差和导出尺寸做定量比较；加强深度置信度与视角一致性，再调整 TSDF 权重及网格简化，避免只靠视觉锐化掩盖几何误差。

**P2：拆分 Activity 与持续验证。** 将相机 session 状态机、查看手势与扫描生命周期拆成可独立测试的控制器；增加 Android 仪器测试覆盖指针变化、超时回退、权限/后台恢复，并建立带真实 NDK/Ceres 的 APK CI。当前 host 编译和算法测试继续作为快检。
