# MobileScan3D VC170 → VC171 核心增量补丁

基线：本次上传的 `MobileScan3D_core_algo_vc170_20261001.zip`，包内版本 `0.13.30-epoch-reanchor`。本次读取到 GitHub 最新提交为 `4329794100c9f0b5c6a36aca829360718f3d2a5c`；已核对关键修改文件与附件一致（忽略 CRLF/LF）。本包不是完整工程，也不是 APK。

## 覆盖方法

1. 备份现有工程的对应源码，确认使用 VC170 基线；已有自行修改时先合并再覆盖。
2. 解压到包含 `app/` 的 Android 工程根目录，覆盖同名文件。包内按真实仓库路径组织：

| 上传源码包路径 | 本增量包 / 工程路径 |
| --- | --- |
| `cpp/cpp/…` | `app/src/main/cpp/…` |
| `java/com/mobilescan3d/…` | `app/src/main/java/com/mobilescan3d/…` |

不要再套一层 `cpp/cpp`。若你的本地模块布局不同，按此表定位对应文件。

3. 在原有 Android/NDK/Ceres/OpenCV 4.12 环境下执行完整 clean/rebuild，勿混用旧 `.so`。模型、第三方库、Gradle 配置、`local.properties` 不在包内。
4. 导出反馈报告确认有 `CorePatch: vc171-continuity-identity reanchor=disabled`。VC171 是本次源码补丁编号；本包没有改动 Gradle 的 `versionCode` / `versionName`，应用设置中仍可能显示 VC170。

## 修改与原因

| 路径（省略 app/src/main/） | 修改 |
| --- | --- |
| `cpp/native_engine.cpp` | 冻结尺度有当前稀疏几何支持时，优先采用该证据；允许短暂缺样后的恢复；EMA 只处理本帧新拟合，输入归一化换域时废弃旧 EMA；禁止保留旧几何却直接改用新尺度；mask 比较补偿目标框运动；复用标定样本和 mask 缓冲；增加补丁诊断。 |
| `cpp/fusion_evidence.h`（新增） | 恢复需 6 个不同曝光的有效几何确认；相邻支持间隔不超过 2 秒、窗口不超过 10 秒；重复/倒序曝光不计数，明确矛盾取消已有确认。不会靠等待自动恢复。 |
| `cpp/scan_policy.h` | 恢复时检查有界采样的整个当前 raw 工作域，避免只在两条标定曲线的交点处“看起来一致”。 |
| `cpp/target_mask_temporal.h`（新增） | 用前后曝光的跟踪框平移和缩放对齐 mask，再检查 IoU、面积和中心偏差；位置/尺寸异常仍拦截。保持原有位姿、逐像素深度和重复壳保护。 |
| `cpp/object_tracker.cpp` | 修正中央 70% 身份模板与搜索图的缩放比例；先在相同采样网格比对中心区域，防止像素相位误差；贴边搜索不拉伸；负 NCC 不再混同“无法判断”；已经通过两帧 ORB 几何确认的旋转目标不再被轴对齐框长宽比误拒。 |
| `cpp/target_reacquirer.h` | 无候选时保持 200 ms 搜索间隔；有候选后最早在 80 ms 后的新曝光复核。仍需两帧几何匹配，不是承诺 80 ms 实机找回。 |
| `cpp/depth_refinement.h` | 无效或零源置信度先标记为无效深度，再滤波和标定；保留合法逆深度 q=0。 |
| `java/com/mobilescan3d/depth/DepthPreprocessor.kt` | 用 256 项归一化表替换逐像素浮点除法，缓存横向色度索引、逐行地址。与 VC170 输入 tensor 逐位一致。 |

另修复标定参考中位数误用 `[0.05,60]` 物理深度范围筛选原始逆深度 q 的问题：逆深度模型允许有限的负值和大值；空采样返回无效值，不能凭空用 q=0 开启标定。epoch 已冻结后不再每帧分配、采样并求这个中位数。

## 验证结果和边界

- 原生主文件、跟踪实现：使用仓库 OpenCV 4.12 / Eigen 头文件通过 C++20 语法检查；JNI 头来自 OpenJDK，Android log/Vulkan 使用声明替身。这不是 NDK 链接或 APK 构建。
- 核心回归、实际 epoch 代码受控输入测试、视觉合成回归均通过；测试源和复现方法见 `tests/vc171/`。
- 合成测试覆盖：同一目标/贴边身份打分、无关纹理拒绝、长时间丢失返回、细长目标 90° 旋转、找回后光流接续、运动补偿后的 mask 及异常 mask 拦截。
- Kotlin 预处理编译及位级输出一致性通过。桌面 JDK 17 微基准最后一轮中位数为 VC170 **1.273 ms/帧**、修改后 **1.152 ms/帧**（约 9.5% 改善，仅此预处理阶段）；不能推算手机整体 FPS 或模型推理速度。
- **未完成**：完整 APK/NDK 链接、实际摄像头/硬件深度/NanoTrack 模型运行、Android 生命周期/并发压力、温升和实物尺度精度测量。

真实尺度冲突时仍会暂停新增几何。移除 VC170 的自动重锚是为了防止把两套换算结果写入同一个模型；尚未实现对既有关键帧重算并重新融合。因此，本包处理已定位的误拒与恢复问题，不能保证所有停建原因都已消除。完全遮挡、低纹理、强反光或大幅改变视角时，也不能保证始终锁定。

## 实机验收与下一步

1. 对有纹理静物连续扫 60 秒，包含横移、靠近/远离和绕行。对比 VC170 的 `targetFuse`、`targetVoxels`、`fusedFrames`、mask 拒绝、`suspendedFrames` 和 `PerfStage`，记录模型是否持续增长及是否出现重复壳。
2. 目标移出画面 1 秒和 10 秒后回到不同位置；再测试细长目标旋转、相似背景、遮挡。记录消失到恢复的真实耗时，检查找回后是否仍是同一物体。
3. 距离约 0.25 / 0.8 / 2 米的验收需要把扫描范围设得足够大；观察 HUD 距离、辅助镜头、重建尺寸与实际测量。补丁未改动镜头调配策略。
4. 若持续暂停，优先提交对应时段的反馈报告和短视频，分清 `depthEarlyNoSnap`、mask 拒绝、epoch 证据不足和 FusionGuard 拒绝。避免直接放宽所有融合门限。
5. 下一轮优先：按实机计时定位推理和全局锁等待的占比；对真正标定漂移引入有限关键帧回放/重新融合；再考虑多视角目标描述和推理后端。此轮未引入这些较大改造。
