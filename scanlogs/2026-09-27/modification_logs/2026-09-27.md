## 本轮修复：定位提示语义错误（V0.13.1）
**bug**：`warningBanner` 文案是常量「定位失锁：位姿不可用于拼接」，显示条件
`scanning && !vinsOk`。VINS **尚未初始化**（刚开扫、还没移动出视差）时也是
`!vinsOk`，用户一开扫就被判「失锁」——语义错误、且让人以为设备坏了。

**修复**：新增「曾初始化过」闩锁以区分两种状态
- `vins/vins_bridge.{h,cpp}`：`vinsEverInitialized()`（solver_flag 进 NON_LINEAR
  即置位）+ `vinsResetInitLatch()`（nativeCreate 时清零）
- `native_engine.cpp`：JNI `nativeVinsEverInitialized`；nativeCreate 调 reset
- `NativeBridge.kt` / `MainActivity.kt`：banner 分两种文案
  - 从未初始化 → 「初始化中：请手持手机缓慢平移，建立定位后开始拼接」
  - 初始化后跟丢 → 「定位失锁：…请回到已扫描区域」

**真机验证 run4（OnePlus PLK110）**：8 次采样全命中「初始化中」，误报 0 次；
崩溃/ANR/F 级错误 0；native create 2 次（冷启动 + startScan，均为预期）。

## 关键发现：前几轮回归是「静止盲区」
run1~run4 全部脚本自动跑、**手机静止**，而 VINS 初始化必须有视差运动。
所以「地图 0 · 绘制 0」不是崩溃型 bug，而是测试条件所致。
佐证：TSDF 侧一直在正常输出（`nativeBuildMesh src=scene verts=10709 tris=19999`，
`src=target verts=920`）；场景点云 `g` 为空是因为融合门控要求 epoch 标定稳定。
→ 结论：此前验证的只是「不崩溃」，**尚未验证「能重建」**。必须手持移动复测。

- **P0-1 深度表示（尺度漂移根因闭环）**：MonoDepthProvider 删除会话级 `globalMin/globalMax`
  动态重映射到 [0.4,6]m，改为直接取模型原始输出 q（固定 `RELATIVE_DEPTH` 语义），
  不再做上采样、不再按单帧 min/max 猜测 linear/inverse。native 侧 `nativeOnDepthMapImpl`
  本就逐像素 `c.toMetric(dv)` 把相对深度转米制，所以喂固定 q → 标定数值域稳定，
  彻底消除「同一 q 随 min/max 扩张映射到不同深度」的尺度漂移根因。
  DepthProvider.Result 去掉 `normA/normB/normVersion`，新增 `representation` 字段；
  MainActivity 删掉 `nativeSetDepthNormMapping` 调用与 `freezeNormalization` 逻辑
  （旧重参数化链路退化为死代码，仍可编译，本轮回填留待清理）。
- **P0-2 256² 原生融合**：不再把 256² 深度上采样到相机分辨率，改为下发 256² 深度 +
  按 深度/相机 比降采样内参 K（`dFx=gFx*rx, dFy=gFy*ry, dCx=gCx*rx, dCy=gCy*ry`），
  `fuseDepth`/`fuseTargetDepth` 直接在深度栅格上 `integrateDepth`，surfel 同样在深度栅格采样。
  几何信息基本无损且省一次上采样。
- **P1-2 体素档位**：新增 JNI `nativeSetVoxelProfile(profile:Int)` 映射
  0=OBJECT_HQ(目标4mm/场景8mm)、1=OBJECT_FAST(8/12mm)、2=ROOM(8/20mm)，并按档位给块预算
  （高分辨率档位给更多块防「半边模型」）。`startScan` 在 `nativeCreate` 之后调用，
  避免被默认体素重置覆盖（nativeCreate 内 tsdf.reset()+setVoxelSize 默认 20mm/8mm）。
